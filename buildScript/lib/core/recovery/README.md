# Staged sysctl write-ahead journal
This isolated Linux module stores only per-interface sysctl restoration intent, not credentials, firewall commands, TC programs or PID-based kill commands. Use the validated state-store directory fd and exclusive supervisor ownership. File publication is write, fsync, rename and directory fsync; malformed or foreign files fail closed. Scope is boot ID plus network namespace identity. The loader never restores any value itself.

Not linked into normal builds yet. Before activation: record intent before every actual sysctl mutation and remove records only after verified rollback; recover only after exclusive listener acquisition, verified absence of the previous children, and native owned-resource reconciliation. Compare live interface identity and current value, never restore global all/default or a replacement link; if ownership is uncertain, report it instead. A matching name and ifindex alone does not eliminate reuse within one boot. Do not recreate Android netd-owned offload filters. Run `bash buildScript/test/root_sysctl_wal.sh` on a Linux host.

## Read-only process recovery gate
`nf_process_guard` checks the recorded boot, net namespace and PID namespace, PID, start time, session/group and executable identity. If a leader is gone it checks whether its process group is still present (signal 0 only, no signal delivered). Ambiguous identities and inaccessible proc data block automatic recovery. It does not enumerate unknown children or guarantee that descendants which changed sessions are gone. Persist child identities from the verified asteriskd launch path before writing sysctls; do not infer them from process names or an overwritten state file. The V2 WAL format now includes child identities and PID namespace in the same atomic file; unsupported V1 files fail closed. Run `bash buildScript/test/root_process_guard.sh` on Linux.

## Combined recovery gate
The coordinator records verified child identities and sysctl restoration intent together before a write. It refuses PID reuse or conflicting original values, retains outstanding records on failed verification, and clears only records already restored or whose old interface is confirmed gone. `nf_recovery_inspect` is read-only: children must be absent before a sysctl is even probed. It does not automatically write a sysctl after a crash. The native lifecycle adapter is a separate experimental patch, not used by standard builds. Run `bash buildScript/test/root_recovery_gate.sh`.
